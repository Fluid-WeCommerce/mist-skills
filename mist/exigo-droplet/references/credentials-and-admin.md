# Credentials per installation, and the admin surface

Credentials live in the droplet's own DB, one row per installation, keyed by `ctx.installation.id` (the `companies` primary key, a string). The SDK reads no env vars and stores nothing; the app supplies credentials. Storage is per installation, so a reinstall creates a new `companies` row and the admin must re-enter the Exigo credentials.

## lib/schema.ts

```ts
export const exigoConnections = pgTable("exigo_connections", {
  installationId: text("installation_id").primaryKey(),

  username: text("username"),
  // AES-256-GCM, keyed by CREDENTIAL_ENCRYPTION_KEY. Never returned to the browser.
  passwordCiphertext: text("password_ciphertext"),
  restBaseUrl: text("rest_base_url"),
  restUsername: text("rest_username"),
  restCompany: text("rest_company"),
  restPasswordCiphertext: text("rest_password_ciphertext"),

```

Add the matching idempotent DDL inside `ensureSchema()` in `lib/ensure-schema.ts` (PGlite locally, Neon in production), in the same `conn.execute(sql\`...\`)` style as the existing tables:

## lib/secret-box.ts

```ts
import { createCipheriv, createDecipheriv, createHash, randomBytes } from "node:crypto";

const KEY_ENV = "CREDENTIAL_ENCRYPTION_KEY";

export class SecretBoxError extends Error {}

function key(): Buffer {
  const raw = process.env[KEY_ENV];
  if (!raw) throw new SecretBoxError(`${KEY_ENV} is not set.`);
  return createHash("sha256").update(raw).digest();
}

export function seal(plaintext: string): string {
  const iv = randomBytes(12);
  const cipher = createCipheriv("aes-256-gcm", key(), iv);
  const enc = Buffer.concat([cipher.update(plaintext, "utf8"), cipher.final()]);
  return ["v1", iv, cipher.getAuthTag(), enc]
    .map((part) => (typeof part === "string" ? part : part.toString("base64url")))
    .join(".");
}

export function open(sealed: string): string {
  const [version, iv, tag, data] = sealed.split(".");
  if (version !== "v1" || !iv || !tag || !data) {
    throw new SecretBoxError("Stored credential is not in the expected format.");
  }
  try {
    const decipher = createDecipheriv("aes-256-gcm", key(), Buffer.from(iv, "base64url"));
    decipher.setAuthTag(Buffer.from(tag, "base64url"));
    return Buffer.concat([
      decipher.update(Buffer.from(data, "base64url")),
      decipher.final(),
    ]).toString("utf8");
  } catch {
    throw new SecretBoxError("Stored credential could not be decrypted. Re-enter the password.");
  }
}
```

GCM is authenticated: a rotated key or tampered value fails to decrypt instead of yielding garbage. Create the key with `fluid mist env set CREDENTIAL_ENCRYPTION_KEY --generate --json` so the value is generated by the CLI and never passes through the agent or the chat. Do not print it, and never edit Mist-managed `DATABASE_URL` or `FLUID_*` variables. Rotating the key makes stored passwords undecryptable, so the admin must re-enter them.

## Resolving credentials for a request

`db()` is async and tables must exist first, so every data-access function awaits `ensureSchema()` and then `db()`.

```ts
import { eq } from "drizzle-orm";
import { db } from "@/lib/db";
import { ensureSchema } from "@/lib/ensure-schema";
import { exigoConnections } from "@/lib/schema";

export async function getExigoConnection(installationId: string) {
  await ensureSchema();
  const conn = await db();
  const [row] = await conn
    .select()
    .from(exigoConnections)
    .where(eq(exigoConnections.installationId, installationId))
    .limit(1);
  return row ?? null;
}

export async function resolveExigoCredentials(installation: Company) {
  const row = await getExigoConnection(installation.id);
  if (!row?.host || !row.database || !row.username || !row.passwordCiphertext) {
    throw new ExigoNotConfiguredError("Exigo is not configured for this installation.");
  }
  assertExigoHostAllowed(row.host);
  return {
    host: row.host,
    port: row.port,
    database: row.database,
    username: row.username,
    password: open(row.passwordCiphertext),
    egressProxy: resolveEgressProxy(installation.authenticationToken),
  };
}
```

No env-var fallback to shared Exigo credentials, ever. A missing row is an error response (409 "not configured"), not a default. The installation and its `authenticationToken` come only from `resolveFluidInstallation` (or an HMAC-verified webhook's installation), never from request body fields.

## Admin routes

- The Droplet Bridge is live, so every credential read, write and test route verifies the signed Bridge session token on the server and refuses a `dri`-only request with 401. The `dri` only finds the installation (`resolveFluidInstallation()`); it never authorises. Verify with `verifySessionToken(token, servingStore)` from `lib/fluid/session-token.ts`, following `app/embed/session-example/route.ts`: expected store from `createFluidClientForInstallation(context.installation).getServingStore(context.companyId)`, never from the token or the browser; later requests may use the short app session from `lib/fluid/embedded-session.ts`. Put this in one shared helper used by GET, PUT and the test route, and fail closed (401) when configuration, token or identity is missing. Do not invent another viewer JWT, OAuth gate or token, and do not add a bypass that can engage in production.
- If the app was created from the Exigo starter, this is already wired; do not add `dri`-only admin routes.

```ts
// lib/admin/session.ts
import { createFluidClientForInstallation } from "@/lib/fluid/client";
import type { FluidInstallationContext } from "@/lib/fluid/installation-context";
import { verifySessionToken, type SessionTokenIdentity } from "@/lib/fluid/session-token";

export class AdminSessionError extends Error {}

// The browser sends the Bridge session token on every admin request; the dri alone is refused.
export async function requireAdminSession(
  request: Request,
  ctx: FluidInstallationContext,
): Promise<SessionTokenIdentity> {
  const token = request.headers.get("authorization")?.match(/^Bearer (\S+)$/)?.[1];
  if (!token) throw new AdminSessionError("Session token required");
  try {
    const store = await createFluidClientForInstallation(ctx.installation).getServingStore(ctx.companyId);
    return verifySessionToken(token, store);
  } catch {
    throw new AdminSessionError("Session token invalid");
  }
}
```

The `Authorization` header is this app's own browser-to-server transport for the Bridge token; never forward that token to a Fluid API (use the installation's DIT). Call `requireAdminSession` right after `resolveFluidInstallation` in GET, PUT and the test route, and map `AdminSessionError` to 401.
- Scope every read and write to `ctx.installation.id`.
- GET returns `{ host, port, database, username, restBaseUrl, restUsername, restCompany, passwordSet: boolean, restPasswordSet: boolean }`. It never returns a password or ciphertext.
- PUT validates the host and `restBaseUrl` (below) before saving, so a bad value never lands in the DB for a later callback to dial.

### Blank password keeps the stored one only if the target is unchanged

A saved password must not be replayed to a destination the admin just changed, or anyone who gets past admin auth could point the stored login at a host they control.

```ts
export function keepsStoredPassword(
  stored: typeof exigoConnections.$inferSelect | null,
  next: { host: string; port: number; database: string; username: string },
): boolean {
  return (
    stored !== null &&
    stored.host === next.host &&
    stored.port === next.port &&
    stored.database === next.database &&
    stored.username === next.username
  );
}
```

- SQL: a blank `password` keeps `passwordCiphertext` only when `keepsStoredPassword` is true; otherwise answer 422 "re-enter the password". A non-blank password is `seal`ed.
- REST: a blank `restPassword` keeps `restPasswordCiphertext` only when `restBaseUrl`, `restUsername` and `restCompany` are all unchanged; otherwise require re-entry.

## lib/admin/exigo-host.ts

The `dri` is a lookup key that travels in an iframe query string; even behind session-token auth, an admin-entered host is untrusted input, so an unchecked field could store any hostname and have the server connect to it. Hostnames only: the proxy refuses IP literals anyway, so refuse every IP literal here (dotted, short-form like `127.1`, integer like `2130706433`, hex, bracketed IPv6) rather than trying to classify private ranges.

```ts
const ALLOWLIST_ENV = "EXIGO_HOST_ALLOWLIST"; // comma-separated hosts or *.suffix

export class ExigoHostError extends Error {}

// Dotted DNS name whose last label starts with a letter: rejects every numeric,
// hex and IPv6 form, and single-label names such as "localhost".
const HOSTNAME = /^(?=.{1,253}$)([a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?\.)+[a-z][a-z0-9-]*$/i;

export function assertExigoHostAllowed(host: string): void {
  const trimmed = host.trim();
  if (!trimmed) throw new ExigoHostError("Exigo host cannot be empty");
  if (!HOSTNAME.test(trimmed) || trimmed.toLowerCase().endsWith(".localhost")) {
    throw new ExigoHostError(
      "Exigo host must be a DNS hostname: no IP address, scheme, path, port or credentials",
    );
  }
  const allowlist = (process.env[ALLOWLIST_ENV] ?? "")
    .split(",").map((e) => e.trim().toLowerCase()).filter(Boolean);
  if (allowlist.length === 0) return;
  const lower = trimmed.toLowerCase();
  const ok = allowlist.some((e) =>
    e.startsWith("*.") ? lower.endsWith(e.slice(1)) : lower === e,
  );
  if (!ok) throw new ExigoHostError(`Exigo host ${trimmed} is not in ${ALLOWLIST_ENV}`);
}

export function assertExigoRestBaseUrlAllowed(baseUrl: string): void {
  let url: URL;
  try {
    url = new URL(baseUrl.trim());
  } catch {
    throw new ExigoHostError("Exigo REST base URL is not a valid URL");
  }
  if (url.protocol !== "https:" || url.username || url.password || url.port) {
    throw new ExigoHostError("Exigo REST base URL must be https with no credentials or port");
  }
  assertExigoHostAllowed(url.hostname);
}
```

Set `EXIGO_HOST_ALLOWLIST` (for example `*.exigo.com` plus the tenant's SQL host) when the tenant's hosts are known; it is the strong control. This is not a complete SSRF defence: a public name whose DNS points inward still passes. The port is a separate integer field (default 1433), and through the proxy the destination port must also be on the proxy's allowlist.
