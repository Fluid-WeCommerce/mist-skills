# Match the actual product UI by default

Use before authoring a website/app screen, adapting another company's video, or correcting a source mismatch. The default is the company's actual UI at the intended viewport and state. A visually plausible brand-themed reconstruction is not enough. Creative staging, camera movement and editorial graphics can change while the product shown inside the screen remains faithful.

## Establish the source states

Record the approved URL/build, capture date, route and exact section, viewport dimensions, scroll/selection state, original markup/styles/media, and any source revision/hash available. Call a homepage section a homepage section; do not present it as an individual product page. Inspect the page's actual rendered state as well as its source. Browser-injected widgets, personalized content and source changes can otherwise confuse the comparison.

For the selected actions, capture the initial, hovered/selected and resulting states as relevant. Resolve the real responsive breakpoint inside each device's virtual screen; a 390px phone inside a 1920px composition must not inherit desktop media queries. A different viewport can legitimately change the layout. Use the actual viewport when comparing it.

## Build from source rather than guessing

Prefer the existing component/source markup and CSS, frozen into an offline, seek-driven composition. Preserve their layout rules, fonts, text case, wrapping, images, responsive asset variants, controls, prices, icons, dividers, corners and crop behavior. Scope source styles so they do not restyle the film or other device screens. Localize required media and remove autonomous scripts, network actions, commerce side effects and wall-clock animation. Drive only the necessary page state and scroll from the film's shared time.

If source components cannot run in the composition, reconstruct from the actual inspected styles and measured geometry, and compare the result to the source. Keep important text/controls native and controllable when that is the deliverable. Exact captured layers or time-indexed frames can preserve static detail or source footage; identify which parts are editable and which are captured. Do not replace unavailable details with a generated or generic UI and call it faithful.

Load the actual available source fonts and wait for them before measuring/capturing. Check font availability on the rendering computer as well as the authoring machine. The source's own declared fallback is different from choosing a substitute for convenience. If required typography or source access is missing, preserve what is verified, identify the affected fidelity gap and resolve it before claiming a matching final result. A neutral starter's Inter font is not permission to replace a company's typeface.

Keep real interaction ordering, selected/expanded states, header collapse/sticky behavior, source image swaps and control positions. Source CSS/JavaScript can establish durations/eases; translate them into deterministic time rather than inheriting autonomous transitions. Derive the cursor target and a flying object's landing from the actual destination geometry, including scroll and responsive state. Avoid hard-coded targets from a prior mockup.

For a moving source hero, use the actual footage in a renderer-supported deterministic form, such as locally indexed frames. A poster is a frozen source state, not an equivalent implementation of moving footage; record a deliberate freeze and its purpose. Do not silently omit prices, Add buttons, navigation items or categories to make the composition cleaner. Frame or scroll the real page instead. Temporary source overlays can be dismissed for capture when appropriate; record that preparation rather than redesigning the core UI.

## Keep editorial treatments distinct

Large benefit headlines outside a device, an ingredient triptych, product cutout flights and a layered page flyover are film treatments. They may use the company's real materials without pretending those layouts are actual product screens. Preserve approved creative motion while changing the screen content back to source fidelity. Do not make the UI itself inherit the previous film's typography, spacing or screen layout.

User-requested UI redesigns and explicitly accepted approximations are valid exceptions. Name the affected parts in the brief. Do not infer permission for approximation merely because the task is a promo, the runtime prefers native elements, or the reference belongs to another company.

## Verify before a final export

Compare undistorted source and composition screen content at the same viewport, scroll, selected state and media time. A perspective device shot can hide layout mismatches. Inspect fonts/case, line wrapping, header state, image crop, controls and spacing; compare important DOM rectangles when source is available. Then inspect the staged shot for perspective, cursor alignment, clipping and motion handoffs.

Record what the comparison establishes. Matching declared colors, asset hashes or source copy does not establish visual fidelity. A small AA/subpixel difference is not a new layout, but report the actual comparison scope/tolerance and do not claim pixel identity unless measured. Source-content provenance, fidelity review, scene checks and final-file verification are separate checks.

Keep a compact `sourceUiStates` list in the brief or source ledger: URL, route/section, viewport, state, font/media status, captured-versus-native layers, comparison evidence and unresolved deviations. Run the focused comparison before calling the source UI matched; keep a full-render hold intact. Recheck only the changed states and connected boundaries after a correction.

Sunrider's correction uses the actual localized page markup/CSS and served Alte Haas font files, with a1440×876 homepage and390×770 shop viewport. Its header, product controls and typography are source UI; phone system chrome and film headlines remain separate layers. These dimensions are this project's measured screen choices, not defaults for other products.
