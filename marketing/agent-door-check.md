# Goal

Personal shopping agents now start at `/.well-known/poppy.json` (Sierra's Personal Agent Protocol, "Poppy", v1.0). Fluid storefronts publish that file on every domain they answer on, and it points the agent to the store's UCP profile, where it can search the catalog, ask questions and build a cart. If the file is missing on one domain, names the wrong host, or points to a profile that fails, the agent falls back to driving the site like a person, or skips the store.

This skill reads those public files on each of {{company.name}}'s domains and reports what an agent would find. It is read-only: it never builds a cart, places an order, signs anyone in, or changes anything in Fluid. Report only what the responses show. Do not quote shares of agent traffic or conversion benchmarks. Today is {{today}}.

# Steps

1. **List the domains the store answers on.**
   - `fluid_api("/api/domains", "GET")` - the custom domains. Keep those whose `verification_status` is `verified`; list the rest as "not live, not checked" with their status. Note which one has `primary` true, and skip a domain that has a `redirection_domain_id` (it redirects; the target is checked instead).
   - Add `{{company.subdomain}}.fluid.app`. If the user names a domain, check that one first.
   - Check at most 6 hosts. Say how many were left out.
2. **Fetch the Poppy file for each host.** `web_fetch` `https://<host>/.well-known/poppy.json`. Record the status. Flag:
   - **Missing:** a 404 or an HTML page instead of JSON. A storefront that is disabled or suspended for billing answers 404 on purpose: say that is a possible cause, and do not call it a bug.
   - **Wrong host:** `organization.domain` is not the host you fetched. Each domain must name itself.
   - **Not HTTPS:** any URL in the document (`organization.logo_uri`, a protocol `endpoint`) that does not start with `https://`.
   - **Wrong version:** `protocol_version` is not `1.0`. Note it; do not call it an error, since the spec may move.
   - **No UCP entry:** `agent.protocols` has no entry of type `ucp`, or `extensions` has no `ucp`.
3. **Follow the pointer.** For each host with a UCP entry, `web_fetch` the entry's `endpoint` (the profile, normally `https://<host>/.well-known/ucp`). Flag:
   - **Profile fails:** not JSON, or an error status.
   - **Different host:** the profile URL is on another host than the Poppy file. Poppy requires the same host.
   - **No Ask:** the profile does not offer `dev.ucp.common.ask`. The Poppy UCP extension needs it.
   - **Version gap:** the profile lists no shopping service, or only versions the user should check against the spec.
4. **Confirm there is something to buy.** `fluid_api("/api/v202604/company/products?filter[status]=active&page[limit]=5", "GET")`. If the store has no active products, say so: a perfect door in front of an empty catalog is not ready. Do not test the cart path here; point to **Agent Checkout Dry Run** for that.
5. **Check the other agent files** the same way, one line each, per host: `https://<host>/llms.txt` and `https://<host>/.well-known/agent-card.json`. Present or missing is enough; do not judge their content.
6. **Output** these headings, in this order:
   - **Verdict** - one sentence: of N hosts checked, how many an agent can enter cleanly.
   - **By host** - a table: host, Poppy file, names itself, UCP profile, Ask offered, llms.txt, agent card. Use Yes / No / Error with the status code.
   - **Fix first** - at most 5 rows: host, what is wrong, who fixes it (merchant: a domain still pending or a store switched off; Fluid support: a live domain with no file or a wrong host).
   - **Not checked** - domains skipped and why, and what this cannot see: whether any particular agent is allowed on the store (that is the merchant's own access policy), whether sign-in through an agent works (Fluid's file declares no sign-in, so agents shop as guests), and whether a purchase completes.
   End by asking whether the user wants the findings written up as a note for Fluid support. Write nothing to Fluid.

# What this skill does not do

It does not edit domains, publish or change the Poppy file, test checkout, or tell the merchant whether a given AI agent is allowed on the store. The Poppy file is generated by Fluid for each domain; there is nothing for a merchant to edit in it.
